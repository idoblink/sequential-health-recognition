About This Project

Sequential Health-State Recognition — Beginner-friendly academic demonstration

Project Statement & Objective

“Analyze sequential patient-monitoring observations and identify patterns corresponding to different health states.”

This academic web application demonstrates how time-series physiological measurements can be ingested from open repositories, organized in SQLite, visualized with Chart.js, and analyzed using transparent sequential rules.

Real Clinical Dataset — VitalDB

All measurements displayed in this system are real, de-identified clinical records from VitalDB.

Clinical Context: This data originates from intraoperative / surgical monitoring in operating theaters, not general ward monitoring. Vitals fluctuate due to surgical events, anesthesia agents, and clinical interventions.

Official Citation:
Lee HC, Park Y, Yoon SB, et al. VitalDB, a high-fidelity multi-parameter vital signs database in surgical patients. Scientific Data. 2022;9(1):279.

Rule-Based Demonstration Algorithm

The analysis engine runs deterministically on the backend in Python:

  • Heart Rate (HR): Normal [60–100 bpm], Warning [50–110], Critical [≤40 or ≥130 bpm].
  • Oxygen Saturation (SpO₂): Normal [95–100%], Warning [90–94.9%], Critical [≤89.9%].
  • Systolic Blood Pressure (NIBP_SBP): Normal [90–140 mmHg], Warning [80–160], Critical [≤60 or ≥180].
  • Diastolic Blood Pressure (NIBP_DBP): Normal [60–90 mmHg], Warning [50–100], Critical [≤40 or ≥110].
  • Body Temperature (BT): Normal [36.0–37.5 °C], Warning [35.0–38.5], Critical [≤34.0 or ≥39.5].
  • Sequential Trend Detection: Identifies sustained increases or decreases across ≥5 consecutive readings within 30-second time gaps.

Simple Architecture Stack

  • Backend: Python with Flask (clean REST JSON API)
  • Database: SQLite via Python's built-in sqlite3 module
  • Frontend: HTML5, Vanilla CSS3, Vanilla JavaScript (no React/Node build steps)
  • Visualization: Chart.js with responsive canvas elements
  • Dataset Loader: Official vitaldb Python package
